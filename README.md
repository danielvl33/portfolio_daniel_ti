# CYBER OPS — Daniel Lopes Soares

Portfólio profissional estático em HTML5, CSS3 e JavaScript, preparado para GitHub Pages sem etapa de build. A identidade CYBER OPS usa preto profundo, azul tecnológico, azul neon e superfícies grafite.

## Arquivos

- `index.html`: conteúdo, navegação e metadados.
- `style.css`: identidade visual responsiva, movimento reduzido e estados de foco.
- `data.js`: perfil, competências, equipamentos, temas acadêmicos, diagramas, experiência e documentos.
- `script.js`: filtros, diagramas ampliáveis, monitor de demonstração e QR Code criado localmente.
- `DESIGN.md`: identidade visual, tokens e padrões de componentes CYBER OPS.
- `assets/`: marca CYBER OPS, logo institucional Afya e fotografias de referência fornecidas pelo proprietário.

## Integridade do conteúdo

- As imagens em `assets/reference/` são referências visuais fornecidas, não fotos de equipamentos pessoais nem comprovação de experiência prática. Cada cartão descreve as limitações da imagem.
- Todos os valores do CYBER OPS MONITOR são gerados no navegador para demonstração; não representam uma rede real.
- Os conteúdos de `ACADEMIC` são temas correlatos. Sem matriz ou histórico acadêmico, não são atribuídos como disciplinas já cursadas.
- Os projetos do laboratório são demonstrações ou estudos; não são apresentados como resultados de experiência profissional.
- WhatsApp e e-mail são os contatos oficiais informados; o perfil GitHub existente no projeto também é mantido. O QR Code é gerado localmente e não consulta serviços externos.
- Três certificados existentes podem ser consultados na central de documentos. O currículo fica indisponível até que seu PDF real seja adicionado ao projeto.
- O portfólio não representa administração dos sistemas hospitalares nem gestão de prontuários.

## Atualização de conteúdo

Edite os dados em `data.js`. Para disponibilizar o currículo, adicione o PDF em `assets/curriculo-daniel-soares.pdf` e informe o caminho em `PERFIL.curriculo` e na entrada de currículo em `DOCUMENTS`. Para cada certificado adicional, inclua o PDF e adicione uma entrada com título e caminho em `DOCUMENTS`.

## Publicação no GitHub Pages

Publique o conteúdo desta pasta na raiz do repositório desejado e selecione **Settings → Pages → Deploy from a branch → `main` → `/(root)`**. O site não depende de servidor nem de ferramentas de build.
